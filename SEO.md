# SEO сайта Блик

## Что обнаружилось на опубликованном сайте

- HTTPS с действующим сертификатом отвечает `200`, `www` перенаправляет на основной домен. HTTP тоже отвечает `200`: в GitHub Pages выключен `Enforce HTTPS`.
- `/robots.txt` и `/sitemap.xml` отвечают `404`.
- В исходном HTML каталога нет ссылок на кейсы; страницы кейсов получают заголовок и текст после запуска JavaScript. Шаблон выдаёт `200` даже для несуществующих кейсов.
- На главной уже есть список услуг, но нет отдельных страниц под поисковые запросы. Большая часть работ посвящена веб-сайтам и графическому дизайну. Для дизайна мобильных приложений пока нет опубликованного кейса.
- На первом экране десктопа одновременно запрашивались 120 кадров (~14 МБ). Заставка ждала до семи секунд. На мобильных дополнительно ждала буфер видео, хотя есть постер.

## Как обновлять и публиковать

`js/data.js` — источник кейсов; `service_content.py` — источник текстов услуг. Из папки проекта:

```sh
python3 build_seo.py
python3 build_seo.py --check
```

Публикуйте вместе исходники и результаты сборки: `index.html`, `works.html`, `cases/`, `services/` и `sitemap.xml`. Текущий GitHub Pages по-прежнему публикуется из корня `main`. Перед отправкой после правок в админке запустите сборку, особенно если заменяли `js/data.js` вручную. При изменении адреса существующего кейса потребуется отдельно сохранить переход со старого адреса.

Старые ссылки `case.html?p=...` открывают новый адрес в браузере. `case.html` служит также для предпросмотра черновиков и исключён из индекса. Неизвестные адреса вида `/cases/...` используют стандартный ответ `404` GitHub Pages. На GitHub Pages нельзя задать HTTP 301 для отдельных параметров запроса, поэтому переход со старых ссылок выполняется в браузере.

## Что сделать после публикации

1. В [GitHub Pages](https://github.com/blick-digital/blick-site/settings/pages) включить **Enforce HTTPS**. Проверить, что HTTP перенаправляет на HTTPS и что формы и медиа загружаются на HTTPS.
2. В [Google Search Console](https://search.google.com/search-console) открыть или подтвердить домен `blickdesign.ru` и отправить `https://blickdesign.ru/sitemap.xml`.
3. Через «Проверка URL» проверить главную, страницу разработки сайтов, страницу айдентики и один кейс; при необходимости запросить индексацию. Затем смотреть отчёты «Страницы», «Эффективность» и Core Web Vitals.
4. Начать с запросов, которые подтверждаются портфолио: разработка сайта для ресторана, сайт концертной площадки, фирменный стиль для кофейни, дизайн упаковки. Спрос и позиции проверить по показам и запросам в Search Console. Добавлять в кейсы реальные сведения о задаче, процессе и результате, где их можно раскрыть.
5. Заменить общие ссылки на Telegram, Instagram и Behance реальными профилями студии, когда будут точные адреса. Добавлять естественные ссылки на кейсы с сайтов клиентов и профильных публикаций, когда это уместно.

Метаописания, карта и ссылки упрощают обход и представление страниц в поиске. Позиции и сроки зависят от спроса, конкуренции и пользы контента. Реклама для органической выдачи не нужна.
